<objective>
Deliver the in-app first-run Python environment provisioning (D-08): the backend detects a missing venv, runs the uv-based setup (the exact recipe verified in Plan 04), and streams progress; the frontend shows a dedicated full-page setup screen with progress, retry, and cancel — modeled on how LM Studio-style apps provision large runtimes in-app. Keeps the installer small (D-08) by downloading the ~5-6GB environment on first launch.

Purpose: Without this, a freshly-installed app cannot transcribe until the user manually runs uv in a terminal — defeating the desktop packaging goal.
Output: /api/setup backend + FirstRunSetup UI wired into app launch.
</objective>

| backend → uv → indexes | uv downloads torch/whisperx/pyannote (~5-6GB) from indexes |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-15-61 | Tampering | uv installs packages during provisioning | high | mitigate | Provisioning runs the fixed recipe/pyproject + explicit cu128 index only (no user-supplied package names); RESEARCH Package Legitimacy Audit reviewed the ML deps; verified end-to-end in Plan 04 |
| T-15-62 | Denial of Service | /api/setup/start spawnable repeatedly or left running after disconnect | medium | mitigate | Single in-flight setup guard; client disconnect/cancel kills the process (Task 1) |
| T-15-63 | Elevation of Privilege | Setup endpoint reachable from a non-localhost origin | low | mitigate | Backend binds 127.0.0.1 only (Plan 01 D-12); no remote clients |
| T-15-SC | Tampering | uv-driven pip installs (supply chain) | high | mitigate | Same as T-15-61 — pinned pyproject + explicit index; no [ASSUMED]/[SUS] arbitrary names |
