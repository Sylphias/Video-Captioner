<task type="checkpoint:human-verify" gate="blocking-human">
  <name>Task 1: First native-Windows GPU resolve + transcription (human-verify)</name>
  <what-built>
    Plan 03 added `register_windows_cuda_dlls()` to scripts/transcribe.py + scripts/diarize.py (Pitfall 1 DLL-directory registration), a `HF_HUB_DISABLE_SYMLINKS` default (Pitfall 2), a `just setup-python-windows` recipe, and a cu128 `[[tool.uv.index]]` block in pyproject.toml (Open Q1). Nothing here has run on real Windows GPU hardware yet — this task is that first run.
  </what-built>
  <how-to-verify>
    Run these steps ON THE NATIVE WINDOWS MACHINE (PowerShell/CMD, NOT WSL), from the repo root checked out on the Windows filesystem:
    1. Ensure `uv` is installed (`uv --version`); if absent, install the standalone uv binary.
    2. Delete any stale venv, then run the Plan 03 recipe: `just setup-python-windows` (or the equivalent `uv venv .venv` + the cu128 torch install + `uv pip install -e .`). Confirm it completes with NO dependency-resolution/index-conflict error (Open Q1). Note the total download size (~5-6GB expected).
    3. Run `just check-env-windows` (or `.venv\Scripts\python.exe -c "import torch; print(torch.cuda.is_available()); import whisperx; print('ok')"`). Confirm `torch.cuda.is_available()` prints `True`.
    4. Transcribe a short (~10-30s) test clip: `.venv\Scripts\python.exe scripts\transcribe.py <path-to-short.mp4> out.json en`. Confirm: (a) it does NOT fail with a `.dll`-not-found OSError/RuntimeError (Pitfall 1 closed), (b) console/logs indicate the CUDA/float16 device path was chosen (not CPU/int8 fallback), (c) `out.json` contains word-level entries with start/end times.
    5. Report: did the resolve succeed cleanly? Did CUDA get used? Any DLL errors? Approximate transcription speed vs. prior WSL runs?
  </how-to-verify>
  <acceptance_criteria>
    - `uv` resolve/install completes with no index/dependency conflict.
    - `torch.cuda.is_available()` is True on the RTX 4080.
    - transcribe.py produces a word-level transcript with no cuDNN/cuBLAS DLL error and uses the CUDA device.
  </acceptance_criteria>
  <resume-signal>Type "approved" if resolve + GPU transcription succeeded, or describe the exact error output (resolve conflict text, or the missing .dll name) so Plan 03 can be revised before Plan 06 builds provisioning UI on top of it.</resume-signal>
