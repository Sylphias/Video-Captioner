Output: A runnable Electron app that boots the backend and shows the web app in a native window.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| renderer (web app) → Electron main | Only the single IPC channel eigen:choose-folder is exposed via contextBridge |
| Electron main → backend child | Config passed via env at spawn; no privileged data |
| loaded content | Main window loads first-party localhost:3001 only — not remote URLs |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-15-51 | Elevation of Privilege | Renderer gaining Node access via nodeIntegration/contextIsolation misconfig | high | mitigate | webPreferences contextIsolation true + nodeIntegration false; preload exposes only chooseFolder (Task 3, RESEARCH Security) |
| T-15-52 | Denial of Service | Second app instance spawning a second backend on the port | medium | mitigate | requestSingleInstanceLock; second-instance focuses existing window (Task 3, D-03) |
| T-15-53 | Denial of Service | Backend fails to become healthy → app hangs on splash | medium | mitigate | waitForBackendHealth bounded timeout + descriptive error surfaced to splash/electron-log (Task 2) |
| T-15-54 | Denial of Service | Backend child orphaned on quit | high | mitigate | shutdownBackend graceful-then-tree-kill (Task 2, Pattern 3) + backend orphan watchdog (Plan 01) |
| T-15-SC | Tampering | npm install of electron, tree-kill, electron-log | low | accept | RESEARCH Package Legitimacy Audit: electron flagged SUS only by a "too-new" heuristic (official org, millions of weekly downloads) — audit explicitly states NO checkpoint required; tree-kill/electron-log verdict OK. Verify exact electron version via npm view at install time. |
