<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| build pipeline → downloaded binaries | ffmpeg/uv fetched from upstream at package time |
| installer → user machine | NSIS writes per-user install + Start Menu entry |
| packaged resources → runtime | backend + binaries loaded from resourcesPath outside asar |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-15-81 | Tampering | Bundled ffmpeg/uv binaries downloaded at build time could be swapped | medium | mitigate | fetch-binaries.mjs pins exact versions from official sources (gyan.dev/BtbN, astral-sh uv releases); versions recorded in build/README.md; single-developer build, no CI supply chain |
| T-15-82 | Denial of Service | asar-packed native module/backend fails to load at runtime (Pitfall 3) | high | mitigate | Ship backend+node_modules+bundle+binaries as extraResources outside asar; asarUnpack for native modules; verified by the install+launch checkpoint (Task 3) |
| T-15-83 | Elevation of Privilege | Installer requiring admin / writing machine-wide | low | mitigate | NSIS per-user (oneClick false, perMachine false) — no admin (D-10, Task 2) |
| T-15-SC | Tampering | npm install of electron-builder, @electron/rebuild | low | accept | RESEARCH Package Legitimacy Audit: both flagged SUS only by the too-new heuristic (official Electron org, millions weekly downloads) — audit explicitly states no checkpoint required; verify exact versions at install time |
</threat_model>
